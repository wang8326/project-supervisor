# Codex 模型路由（本地默认策略，2026-10-08）

仅用于监管/执行任务的 Codex 模型选择，不修改业务产品的供应商模型、API 参数或全局 Codex 配置。

## 默认分配

| 工作 | 默认模型 | 推理 |
|---|---|---|
| 日常只读监管、排期、范围与普通验收判断 | `gpt-6.1-sol` | `high` |
| R3 实现、复杂跨模块根因、高风险最终审查 | `gpt-6-astra` | `high` |
| 范围明确的日常开发 | `gpt-6.1-sol` | `medium` |
| 机械文案、格式或其他低影响变更 | `gpt-6-luna` | `low` / `medium` |

监管涉及多源风险与验收判断，High 是本地可靠性偏好，较慢且消耗更多 token，不保证正确；机械事实整理不承担监管决定。

风险、复杂度和证据缺口决定升级；版本号大小不是能力排序，不因模型较新就把全部工作改用最大模型，不自动启用 Max/Ultra。高风险最终审查仍是只读监管工作，不能借审查身份执行修改或重跑构建。

## 实际可用性与偏好

- 明确用户模型偏好优先。已有项目固定模型规则继续有效；个人 Skill 更新不覆盖它们，冲突应提出单独的项目治理更新任务，不顺手改仓库。
- 派发前核对目标 host 的当前任务创建能力/模型设置；旧工具列表的缺项不能证明模型不可用，也不要据新列表推断其他 host 已支持。无法核实时写“未知”，不要声称已切换。
- 记录请求模型和运行时可核实的实际 model/reasoning；运行时不可见时说明自报限制。守卫接收模型字符串不构成模型认证，也不需要为文档路由添加脚本硬编码注册表。
- 目标模型不可用时说明具体限制，沿用已有且满足风险要求的授权选择；若没有这样的选择，再询问。不得默默替换用户明确指定模型。

## 官方依据与适用边界

核对日期：2026-10-08。[官方模型说明](https://learn.chatgpt.com/docs/models)推荐可用时以 GPT-6.1 Sol 处理复杂 coding/agent 工作，以 Luna 处理明确、重复的任务，保留 Astra 处理最困难工作；5.6 Sol/Terra/Luna 在 rollout 期间仍可用，不能概括为全部失效。[GPT-6.1 Sol API 页](https://developers.openai.com/api/docs/models/gpt-6.1-sol)描述其以较低成本提供接近 Astra 的表现，API 推理档位为 `low`、`medium`、`high`、`xhigh`、`max`。[模型选择指导](https://developers.openai.com/api/docs/guides/model-selection)要求按质量、时间与成本取舍，并建议用相同任务比较。

上表的角色分配与默认推理是本地节省额度和可靠性策略，不是官方强制迁移，本次没有独立 A/B 性能验证，也不保证任何账户或 host 的可用性。官方 API 档位与 Codex host 设置各自核对；本次路由更新不迁移 API 参数。
